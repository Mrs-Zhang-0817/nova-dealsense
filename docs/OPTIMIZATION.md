# 第三阶段优化口径
现有 services/finance.calculate 以 Decimal 在 80 位精度下计算，按订单汇率逐行折算后四舍五入到 8 位。制造成本需已确认，其他成本需已确认且纳入。汇率为每单位基础币对应的报价币。优化器复用同一入口，并拒绝在有未确认纳入成本时推荐方案。
## 迁移设计
新增 optimization_runs 和 scenarios，不修改已有订单数据。运行记录冻结订单输入、成本、汇率、起运与目的市场、约束、搜索边界及算法版本。方案保存全部已评估候选的变量、财务和约束检查。订单删除后历史按运行 ID 仍可读取。
## 搜索与成本
价格网格从 price_min 起按步长递增。数量同理。枚举顺序为数量、物流输入顺序、价格。上限 1000 个候选；截断时仅报告已检查结果。利润优先按贡献利润降序；买家匹配按价格、数量及交付天数相对偏差的等权平均升序；低风险按产能占用率和交期占用率的等权平均升序。交付参照值为填写的客户交期。相同分数按利润降序、单价、数量、物流名称升序。
原有附加成本均为订单行总额。若授权数量发生变化，必须逐项标记 fixed 或 per_unit（根据原始数量按比例缩放）。物流报价使用报告币种的整单费用，显式替换所有纳入的物流类别行；空报价保留订单物流费用。填写者须确认其他类别不含重复运费。调整项仅用于已有成本的数量行为，不接受无来源的制造成本折扣。
反推价格按订单成本除以数量及一减目标贡献率，再向上取到允许网格。各候选仍逐项检查实际利润、贡献率、单价上限、总预算、MOQ、协商范围、产能和交期。缺少交付数据或无法解释的原订单硬约束将阻止推荐。
